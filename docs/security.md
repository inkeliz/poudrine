# Security and network placement


**Keep the package repository and Management off the public Internet.** Package downloads and the first inventory report from each client address rely on your network access controls. A malicious or misconfigured client can request or report a large part of the ports tree. That can consume build time, CPU, disk space and upstream bandwidth long after the request finishes. The download cache limit covers cached archives only. Jail storage, distfiles, dependency builds and the local package repository can all grow independently.

- Bind the repository to a LAN or VPN interface and restrict its port to trusted client addresses with your firewall. Bind the website and Management to loopback or an administrator-only network. The default IPv6 addresses `[::]:8080` and `[::]:8181` listen on **every IPv6 interface**, including globally reachable ones. Configure the listeners **before the first start**.
- **The repository signing key lives in the network-facing process.** The same service process handles package requests, serves the website and signs the merged catalog. It holds the private key in memory and can read `repository.key` in its state directory. Compromise of that process or its service account lets an attacker sign a malicious catalog pointing clients at packages they would trust. Protect the host and its backups. After a signing-key compromise, restore a trusted server, rotate the key and replace the trusted public key on every client through a trusted channel.
- The privileged Poudriere worker has its own build signing key and root-controlled directories. Management uses a separate Ed25519 administrator key. Its private half stays with the administrator, and the browser signs each management request. This protects management operations. Ordinary repository clients can still add build work without an administrator signature.
- Client inventory is self-reported. The first accepted report pins the client’s Ed25519 public key to its observed IP. Later reports from that IP require the same key. Keep the report key across reinstalls. Clients behind one NAT share an observed address, so use distinct LAN or VPN addresses for independent reports. Use a trusted host audit when you need to verify what a client runs. A direct HTTP repository sends package names, versions and origins in cleartext. Use a private VPN or a restricted HTTPS reverse proxy for confidentiality on shared networks.


When using a reverse proxy, configure `trusted_proxy` with only that proxy's address or network. Poudrine accepts `X-Real-IP` from those peers; the proxy must overwrite that header with the observed client address. Networks covering every IPv4 or IPv6 address are rejected. Leave `trusted_proxy` empty for direct connections.

Upstream HTTP redirects stay on the configured mirror hostname and port, except for a standard HTTP-to-HTTPS upgrade. HTTPS cannot redirect back to HTTP. Configure the final mirror URL if a provider redirects to another host. Explicitly configured LAN mirrors remain supported; use HTTPS and trusted DNS for the upstream itself.

Inventory uploads are limited to four concurrent reports, with at most one from each observed client address. The limit covers body reads, signature verification, parsing and database writes. Excess reports receive HTTP 429 and can retry after ten seconds. Each report remains limited to 8 MiB; these bounds do not replace network access controls.

Client activity expires after 180 days. An hourly cleanup removes old requests, installed-package reports and inactive client entries. Pinned report keys remain after activity expires: a returning client must still use its original key. Cleanup also preserves tracked build targets. The dashboard loads clients in pages of 25 and searches across retained clients.

Repository connections are limited to sixteen per TCP peer, with a 30-minute connection lifetime. A reverse proxy shares that peer limit across its clients. Once a response starts sending, it must deliver at least 16 KiB/s within successive 30-second budgets; idle writes also time out after 30 seconds. Upstream bytes can stream to clients before the archive finishes downloading, so upstream stalls can also exhaust a response transfer budget.

Up to sixteen distinct upstream archives can download concurrently. Requests for the same checksum share a live download, with independent positions for ordinary and ranged reads. Arriving bytes go directly to a shared private temporary file; each reader has its own offset and waits for new bytes as needed. Package payloads are not retained in Go heap buffers. Temporary download space is additional to the persistent cache limit. Only fully verified archives enter that cache.

Streaming sends an archive prefix before its checksum can be verified. Poudrine withholds the final response byte, including for range responses, until the complete archive passes its signed size and checksum checks. Failure aborts the response as incomplete. Clients must still verify the catalog checksum before using an archive. Bootstrap signatures are generated only after complete verification.
